# CCR WP-09-2 — Query relevance in the temporal arm

**Status: APPROVED** (orchestrator, WP-09 review round 1). Joins the Phase 2 CCR batch; WP-15 implements it in
the adapters.

## Problem
`port.TemporalQuery` selects units by time alone. Hindsight's temporal arm takes its in-window pool at
cosine similarity >= 0.1 to the query, so a "what did Alice eat last week" recall doesn't fill its
temporal candidates with unrelated facts that merely happened last week.

## Proposed diff (internal/port/queries.go)
```diff
 // TemporalQuery is one temporal-arm search: units whose occurrence (or mention) overlaps Window.
 type TemporalQuery struct {
 	// Bank is the bank searched.
 	Bank BankRef
 	// Window is the time window; at least one bound is set.
 	Window domain.TimeWindow
+	// Embedding is the query vector (domain.EmbeddingDim floats); nil = no relevance filter.
+	Embedding []float32
+	// MinSimilarity keeps only in-window units whose cosine similarity to Embedding is at least this
+	// (Hindsight: 0.1); 0 = none. Units without an embedding never pass a non-zero floor.
+	MinSimilarity float64
 	// Buckets spreads hits evenly over this many sub-windows; 0 or 1 = no bucketing.
 	Buckets int
```
- **Postgres:** add `AND 1 - (embedding <=> $q) >= $min` to the window query when `Embedding` is set and
  `MinSimilarity > 0`. The score and bucketing stay as decision 122 describes.
- **Fake:** apply the same cosine filter.
- **porttest:** an in-window unit below the floor is excluded; nil Embedding means no filter.

## Affected WPs
- **WP-09:** `temporal.Retrieve` sets `Embedding: q.Embedding, MinSimilarity: 0.1`. This is a one-line
  follow-up once the fields exist. It can't be passed today without editing the frozen port, so it isn't.
