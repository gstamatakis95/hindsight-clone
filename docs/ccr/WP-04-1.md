# CCR WP-04-1 — Keep explicit list clears through jsonb (drop `omitempty` on clearable lists and maps)

**Status: PROPOSED** (WP-04). WP-04 does not depend on it to pass its own tests; the bug shows up only once
a config level is persisted (WP-01 adapter, WP-06 UpdateBankConfig / UpdateTenantConfig).

## Problem
Decision 010 says a non-nil empty slice in `BankConfig` is an explicit clear ("as a FieldMask path would
set"), and SPEC says a FieldMask is "also how a list is cleared". `config.ApplyMask` produces exactly that:
masking `entity_labels` with an empty value stores `EntityLabels: []EntityLabel{}` on the bank, so the merge
replaces the tenant's labels with none.

But the bank's overrides, the tenant config, document overrides and operation overrides are all stored as
jsonb by marshalling `domain.BankConfig`, and every list/map field carries `omitempty`. `encoding/json` omits
an empty slice exactly like a nil one, so after a round trip the clear is gone (nil = inherit), and the
tenant's list silently comes back. A user who cleared a list sees it reappear on the next read.

## Proposed diff
`internal/domain/config.go` and `internal/domain/scope.go`: drop `omitempty` from the list/map fields
where "empty" means "clear". `encoding/json` then writes nil as `null` and empty as `[]` / `{}`, and
unmarshalling keeps the distinction (`null` -> nil, `[]` -> non-nil empty).

```diff
-	EntityLabels []EntityLabel `json:"entity_labels,omitempty"`
+	EntityLabels []EntityLabel `json:"entity_labels"`
-	ConsolidationStrategies []ConsolidationStrategy `json:"consolidation_strategies,omitempty"`
+	ConsolidationStrategies []ConsolidationStrategy `json:"consolidation_strategies"`
 (RecallConfig)
-	StrategyBoosts map[string]float64 `json:"strategy_boosts,omitempty"`
+	StrategyBoosts map[string]float64 `json:"strategy_boosts"`
-	EnabledStrategies []string `json:"enabled_strategies,omitempty"`
+	EnabledStrategies []string `json:"enabled_strategies"`
 (ReflectConfig)
-	EnabledTools []string `json:"enabled_tools,omitempty"`
+	EnabledTools []string `json:"enabled_tools"`
 (ObservationScopes, scope.go)
-	Custom []TagSet `json:"custom,omitempty"`
+	Custom []TagSet `json:"custom"`
```

`BankConfig.Models` keeps `omitempty`: models merge per slot, so an empty list clears nothing and nil and
empty mean the same.

Add a domain test: marshal/unmarshal a `BankConfig` with each of those fields set to a non-nil empty value
and assert it comes back non-nil and empty, and that nil comes back nil.

## Affected WPs
- WP-01 (Postgres adapter): no code change if it marshals `domain.BankConfig` with `encoding/json`; the
  porttest round-trip of configs should add an empty-list case.
- WP-02 (fakes): none if the fake stores values (it should deep-copy, not JSON).
- WP-06 (server): the proto→domain conversion should map a masked empty repeated field to a non-nil empty
  slice, or simply pass the mask to `config.ApplyMask`, which already does that.
- jsonb rows written before the change carry no explicit clears, so nothing to migrate.

## Alternatives
- Custom `MarshalJSON` on `BankConfig`: more code for the same effect.
- Store the FieldMask next to the config: a schema change for no extra benefit.
