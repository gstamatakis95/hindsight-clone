# CCR WP-11-1 — Typed context-window overflow error

**Status: PROPOSED** (WP-11). Not blocking: WP-11 detects the overflow by error text meanwhile (decision 1101).

## Problem
SPEC Behavioural rules (Reflect): "An empty final answer, or a model that cannot drive tool calls, also
fails. A context-window overflow does not: the agent synthesises from what it has." The gateway maps every
non-retryable 4xx to `domain.ErrUnavailable` (decision 301, "Known gap"), so an overflow can't be told apart
from any other failed call through the port. WP-11 matches the provider's error text, which the gateway keeps
in the message. That works for the common providers but is brittle (providers reword their errors).

## Proposed diff
`internal/domain/errors.go`:

```diff
 	// ErrUnavailable: a dependency (database, gateway, embedder, reranker) failed. gRPC UNAVAILABLE.
 	ErrUnavailable = errors.New("unavailable")
+	// ErrContextOverflow: the prompt did not fit the model's context window. Wraps ErrUnavailable, so callers
+	// that don't handle it see a failed dependency; reflect synthesises from what it has instead.
+	ErrContextOverflow = fmt.Errorf("%w: context window exceeded", ErrUnavailable)
```

`internal/adapter/gateway` (classify): a non-retryable 400/413 whose body matches the overflow markers
(`context_length_exceeded`, `maximum context length`, `prompt is too long`, `input is too long`, ...) wraps
`domain.ErrContextOverflow` instead of `domain.ErrUnavailable`. `internal/fake` needs nothing: tests script
`Reply{Err: domain.ErrContextOverflow}`.

`internal/engine/reflect/loop.go` (WP-11, after approval): `isContextOverflow` becomes
`errors.Is(err, domain.ErrContextOverflow) || <text match>`; the text match can then be dropped.

## Affected WPs
WP-03 (gateway classify), WP-11 (reflect), WP-12 (agentic refresh inherits the behaviour through reflect).
Additive: no existing caller changes behaviour, since the new error still matches `ErrUnavailable`.
