# CCR WP-07-1 — Report token usage on a synchronous RetainResponse

Status: proposed (not blocking WP-07)

## Problem
SPEC "Model routing" says every LLM call records slot, model and tokens on the operation, so per-slot cost is
visible. A synchronous Retain extracts inline (EXTRACT, TIME_PARSE, EMBED) and returns `RetainResponse`, which
has no usage field. If the sync path creates no operation row, the eval harness can't see memd's extraction
cost at all. Stock Hindsight's retain response does report usage, so a side-by-side report makes memd look
cheaper than it is. Async retain avoids this, since its usage lands on `retain_document` operations, but the
spec's eval barrier requires sync Retain.

## Exact diff
`api/memory/v1/memory.proto`, additive (passes `buf breaking`):

```diff
 // RetainResponse reports per-document outcomes.
 message RetainResponse {
   // One entry per item. Sync: fully filled; async: document and operation ids only.
   repeated RetainedDocument documents = 1;
   // retain_batch parent operation; set when there was more than one document.
   string parent_operation_id = 2;
+  // Token usage per slot and model of the LLM and embedding calls a synchronous retain made; empty when
+  // run_async (the usage is then on the retain_document operations).
+  repeated SlotUsage usage = 3;
 }
```

Then `make gen`. This requires `import "memory/v1/common.proto"`, which memory.proto already has.

The alternative needs no proto change: the sync path records a COMPLETED `retain_document` operation that
carries the usage. That costs an extra row per retain and blurs "operations are background jobs", so the
field is preferred.

## Affected WPs
- WP-08 (Retain engine): returns the usage it already collects for operations.
- WP-06 / WP-14 (server): copies it into the response.
- WP-07 (eval): `target.Memd.Retain` returns it, under the slot names it already uses (a one-line change).
  Until then, the report shows memd usage for REFLECT, background operations (CONSOLIDATE, ...) and JUDGE
  only, and the README and decision 702 say so.
