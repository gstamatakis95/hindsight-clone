# CCR WP-13-2 — `Blob.List` for fenced, paged bank blob deletes

**Status: PROPOSED** (WP-13, review round 1 item 5).

## Problem
`delete_bank` removes the bank's blobs with one `Blob.DeletePrefix("{tenant}/{bank}/")` after checking that
its job is alive and the bank is still tombstoned. On a large bank that call runs for a long time with no
fence: if a duplicate run finished the bank and a client write recreated it, with new blobs under the same
prefix, the running `DeletePrefix` would delete them (data loss in the fresh bank). Deleting page by page with
the fence re-checked between pages bounds the window to one page, but `port.Blob` cannot list keys.

WP-13 already declares the consumer interface `bank.BlobLister` with the proposed method and uses it when
`DeleterConfig.Blobs` is set (test `TestDeletePagesBlobsWithFencing`); without it the deleter falls back to
`DeletePrefix`.

## Proposed diff
`internal/port/blob.go`:
```diff
 	// DeletePrefix removes every object whose key starts with prefix (bank delete: "{tenant}/{bank}/",
 	// domain.BankBlobPrefix) and returns how many it removed.
 	DeletePrefix(ctx context.Context, prefix string) (int, error)
+	// List returns up to limit keys that start with prefix and sort strictly after after ("" = from the
+	// start), in ascending key order. An empty result means no key is left.
+	List(ctx context.Context, prefix, after string, limit int) ([]string, error)
 }
```

- **S3 adapter (WP-03):** `ListObjectsV2` with `Prefix = prefix`, `StartAfter = after`, `MaxKeys = limit`
  (keys come back in UTF-8 binary order, which is Go string order).
- **Fake (WP-02):** sort the stored keys, filter by prefix and `> after`, cut at limit; plus a porttest case
  in the blob suite (ordering, StartAfter, limit, prefix isolation).

## Affected WPs
- WP-02 (fake + porttest), WP-03 (S3 adapter).
- WP-14: pass the blob store as `DeleterConfig.Blobs` once `port.Blob` has `List`.
