# CCR WP-11-2 — `port.Reader.GetChunks` for the expand tool

**Status: PROPOSED** (WP-11). Not blocking: expand works without chunks until it is wired.

## Problem
The reflect `expand` tool (SPEC Engines > reflect: "search_mental_models, read_mental_models,
search_observations, recall, expand, done"; tool description: "the source text chunk a memory was extracted
from, and the source facts an observation was built from") needs to read chunks by id. `port.Reader` has
`GetUnits` (which covers the source facts via `Unit.SourceIDs`) but no chunk read; `ChunkRepo` only has
`Committed` and `Insert`, inside a write transaction. Recall's `include.chunks` (WP-09) needs the same read.

WP-11 declares the consumer interface in its own package:

```go
// internal/engine/reflect/tools.go
type ChunkReader interface {
	GetChunks(ctx context.Context, b port.BankRef, ids []port.ChunkID) ([]domain.Chunk, error)
}
```

and `DefaultTools(rc, pages, r, chunks ChunkReader)` leaves chunks out of expand while `chunks` is nil.

## Proposed diff
`internal/port/store.go`:

```diff
 	GetUnits(ctx context.Context, b BankRef, ids []UnitID) ([]domain.Unit, error)
+	// GetChunks returns the chunks with the given ids, in the order of ids; unknown ids (or chunks of another
+	// bank) are skipped, not an error.
+	GetChunks(ctx context.Context, b BankRef, ids []ChunkID) ([]domain.Chunk, error)
 	// BankSeq returns the bank's latest committed change_seq (0 for a new bank). Unknown bank:
```

Postgres: `SELECT ... FROM chunks WHERE tenant_id = $1 AND bank_id = $2 AND id = ANY($3)`, re-ordered by the
input. Fake: a lookup in its chunk map. porttest: one case (order kept, unknown and other-bank ids skipped).

## Affected WPs
Follow-up package (port + Postgres + fake + porttest), WP-09 (can use it for include.chunks), WP-14 (passes
`store.Read()` as the ChunkReader to `reflect.DefaultTools`).

## Spec lines
Engines > reflect (tools), gRPC surface (ReflectResponse trace tool outputs), Ports > Reader.
