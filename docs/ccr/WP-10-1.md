# CCR WP-10-1 — Observation reads and deletes for consolidation

## Problem
The consolidation engine needs six reads and writes that the frozen ports lack. Until this CCR lands,
`internal/engine/consolidate/extras.go` declares them as consumer interfaces. They are `ObservationCounter`,
`ScopeLister`, `ModelLister` and `ObservationClearer`. Tests implement them over the fake's searches. With
no implementation wired:
- a scope with `max_observations_per_scope` fails its run with FAILED_PRECONDITION;
- `StrategyMatcher.Preview` fails with FAILED_PRECONDITION;
- consolidation triggers no mental-model refreshes;
- the `Invalidator` can't be constructed usefully.

| Need | Spec lines |
|---|---|
| Count a scope's observations for the cap | Feature scope ("caps"); BankConfig `max_observations_per_scope`; the CONSOLIDATE capacity note |
| List a bank's scopes for Preview (and the ListScopes RPC, already expected in the Phase 2 batch) | `PreviewConsolidationStrategies`, `StrategyPreview.Complete`, `ListScopes` / `ScopeInfo` |
| List a bank's mental models for the refresh triggers (and `ListMentalModels`, already expected) | Jobs table: consolidate "triggers refreshes of stale models"; `refresh_after_consolidation` |
| Scopes of the observations citing given units (`Invalidator` return values) | Engines: `ClearForMemory` / `ClearDocumentUnits` return the affected scopes |
| Delete every observation of given scopes and reset their sources | `Invalidator.ClearScopes`; `ClearObservations` RPC ("empty = all") |
| A document's live unit ids | `Invalidator.ClearDocumentUnits`; Behavioural rules (UpdateDocument clears the document's observations) |

## Exact diff (internal/port)

```go
// queries.go / store.go — Reader
type Reader interface {
	...
	// CountObservations returns how many live observations scope s holds (its exact tag set, scope_key).
	CountObservations(ctx context.Context, s ScopeKey) (int, error)
	// ListScopes pages b's observation scopes (observation_scopes rows), ordered by scope key, with their
	// observation and unconsolidated-unit counts; next is "" on the last page. Unknown bank: ErrNotFound.
	ListScopes(ctx context.Context, b BankRef, pageSize int, pageToken string) (scopes []domain.ScopeInfo, next string, err error)
	// ListMentalModels returns every mental model of b, ordered by id. Unknown bank: ErrNotFound.
	ListMentalModels(ctx context.Context, b BankRef) ([]domain.MentalModel, error)
}

// repos.go — EvidenceRepo
type EvidenceRepo interface {
	...
	// CitingScopes returns the distinct scopes of b's observations that cite any of ids.
	CitingScopes(ctx context.Context, b BankRef, ids []UnitID) ([]ScopeKey, error)
	// DeleteScopes deletes every observation of b whose scope is one of scopes (every observation when
	// scopes is empty), clears consolidated_at on their live sources and returns the deleted observations
	// and the reset sources (sorted). Like DeleteCiting it never touches observations of other scopes.
	DeleteScopes(ctx context.Context, b BankRef, scopes []ScopeKey) (deleted, reset []UnitID, err error)
}

// repos.go — UnitRepo
type UnitRepo interface {
	...
	// DocumentUnits returns the ids of doc's live units, sorted.
	DocumentUnits(ctx context.Context, b BankRef, doc DocumentID) ([]UnitID, error)
}
```

With these in place, WP-14 wires the consumer interfaces as thin adapters:
- `CountObservations` -> `Store.Read().CountObservations`;
- `Scopes(b, limit)` -> one `ListScopes` page, where complete = (next == "");
- `MentalModels` -> `Store.Read().ListMentalModels`;
- the three `ObservationClearer` methods -> `tx.Evidence()` / `tx.Units()`.

A later cleanup may replace the consumer interfaces with the port methods.
