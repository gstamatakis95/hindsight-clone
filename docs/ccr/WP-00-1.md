# CCR WP-00-1 — Approve golang.org/x/text for NFC tag normalization

**Status: APPROVED** (orchestrator, review round 1) and applied on `wp/WP-00-contracts`:
`golang.org/x/text` is a direct requirement, `domain.NormalizeTag` applies NFC, and `TestNormalizeTagNFC`
covers it.

## Problem
The Ports block says tags are "normalized by domain.NormalizeTags: NFC, trimmed, lowercased,
deduplicated, sorted". The Go standard library has no Unicode normalization. Without NFC, a precomposed
"é" (U+00E9) and "e" + U+0301 become two different tags and two different observation scopes.
`golang.org/x/text` is not on the approved dependency list. It is already in the module graph as an
indirect dependency of grpc, but using it directly needs approval.

## Proposed diff
`go.mod`: promote `golang.org/x/text` from indirect to a direct requirement (the version grpc already
pulls in).

`internal/domain/tags.go`:

```diff
 import (
 	"slices"
 	"strings"
+
+	"golang.org/x/text/unicode/norm"
 )
@@
-// NormalizeTag trims and lowercases one tag. Unicode NFC normalization is pending CCR WP-00-1
-// (golang.org/x/text is not an approved dependency yet).
+// NormalizeTag applies Unicode NFC, then trims and lowercases one tag.
 func NormalizeTag(tag string) string {
-	return strings.ToLower(strings.TrimSpace(tag))
+	return strings.ToLower(strings.TrimSpace(norm.NFC.String(tag)))
 }
```

`internal/domain/tags_test.go`: add a case where `NormalizeTags([]string{"é", "é"})` returns
one tag.

The `domain` depguard rule only forbids `memd/internal`, so no lint change is needed.

## Affected WPs
- WP-00 (domain).
- WP-01 and WP-02: stored tags and scope keys. Both are new, so there is no migration.
- WP-08, WP-09 and WP-10, which normalize tags through domain. Nothing changes for them beyond the
  behaviour.

## Why the spec allows it
The Ports block names NFC explicitly. This closes a gap between the spec and the dependency list.
