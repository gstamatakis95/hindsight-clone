# CCR WP-08-1 — `UnitRepo.IDsByDocument`: list a document's live units without touching them

Status: approved in the Phase 2 CCR batch (WP-15 implements it); WP-08 switches to it after WP-15 merges

## Problem
When retain replaces a document, it must call `EvidenceRepo.DeleteCiting(ids)` on the document's old units
before `UnitRepo.DeleteByDocument`, because evidence rows cascade on unit delete. No port method lists a
document's unit ids. WP-08 gets them from `UnitRepo.SetDocumentTags` (decision 802). That works, but it
writes to rows that are about to be deleted, and it rewrites the tags of the document's archived units.
ReprocessDocument (WP-13) needs the same list.

## Exact diff
`internal/port/repos.go`:

```diff
 type UnitRepo interface {
 	...
+	// IDsByDocument returns the ids of the document's live units (facts), in id order; an unknown
+	// document has none. It writes nothing.
+	IDsByDocument(ctx context.Context, b BankRef, doc DocumentID) ([]UnitID, error)
 	// DeleteByDocument removes a document's units, ...
```

The Postgres adapter needs one sqlc query (`SELECT id FROM memory_units WHERE tenant_id = $1 AND bank_id = $2
AND document_id = $3 ORDER BY id`). It also needs a fake method and a porttest case.

Then, in `internal/engine/retain/retainer_write.go` `replace`, swap `SetDocumentTags` for `IDsByDocument`.
That is a one-line change.

## Affected WPs
- WP-01 / WP-02 follow-up: adapter, fake and porttest.
- WP-08: the one-line switch.
- WP-13: ReprocessDocument may use it.
