# WP-13 · Bank, curation, documents, maintenance engines — plan

Branch `wp/WP-13-bank-curate-docs-maint`. Owns `internal/engine/bank/**`, `internal/engine/curate/**`,
`internal/engine/docs/**`, `internal/engine/maintenance/**` (plus their regenerated mocks under
`internal/mocks/engine/{bank,curate,docs,maintenance}`). Reads: SPEC "Curation", "Behavioural rules"
(banks and documents), "Jobs" (delete_bank, graph_maintenance), gRPC surface (bank, documents, memory
units), Hindsight `graph_maintenance.py`.

## Ground rules for this package set

- Reads the ports don't have yet go through consumer-declared interfaces whose methods are exactly the
  `port.Reader` methods proposed in CCR WP-13-1 (same name, parameters, results). Their query types are
  declared here for now; once the CCR lands they move to `port` and these become aliases. Tests use small
  in-package stubs for them (decision 1300).
- A tombstoned bank reads as `domain.ErrNotFound` on every read path (Banks().Get + Deleting() check where
  the read is not CCR-backed; CCR-backed reads carry the rule in their contract).
- No job handler calls `Banks().Ensure`: only API-side writes may create a bank.
- Every tx that enqueues calls `tx.Seq(bank)` first (except the tombstone, where Seq would refuse).
- InTx callbacks reset captured results at the top (InTx may re-run them) and never call a model.
- Payloads, serial keys and dedupe per job kind are in decision 1301.
- Refresh enqueues (WP-12 payload) and reprocess (WP-08 payload) go through consumer interfaces
  (`RefreshQueuer`, `Reprocessor`), decision 1303.
- The server's admin interfaces use server-named types (`ConfigPatch`, `ListDocumentsRequest`, ...); Go
  can't satisfy them structurally without importing `internal/server`. Identical types are declared here
  and WP-14 turns the server's into aliases (decision 1302).

## Interfaces implemented

- bank: `TemplateCodec`, `DirectiveSelector`, `DirectiveAdmin` (= server.DirectiveAdmin structurally),
  `TenantAdmin`, `BankAdmin`, `StatsReader`, `PromptPreviewer`, `BankDeleter`.
- curate: `MemoryLister`, `Curator`, `Rederiver`, `ObservationAdmin`.
- docs: `Retagger`, `DocumentAdmin`.
- maintenance: `GraphMaintainer`.
- `worker.ConsolidationCandidates` is satisfied directly by `port.Reader` once CCR WP-13-1 adds
  `BanksToConsolidate` (no wrapper needed).
