# WP-18 plan: consolidation-triggered refresh payload, and the scope re-check before stamping (FX-1 + FX-2)

## Problems
- **FX-1 (final review B, C1).** Consolidation enqueued `refresh_mental_model` as `{"model_id":...}`, but
  `mentalmodel.RunJob` reads `mental_model_id`. Every refresh that consolidation triggered failed at once,
  and the maintenance reconcile then paused the model.
- **FX-2 (final review B, H2).** A unit was stamped consolidated at its last scope without re-checking
  the earlier scopes this run had written. A ClearObservations, or a co-source invalidate or retag, could
  delete such an observation mid-run. That resets the unit but leaves its seq unchanged, so the unit was
  stamped with nothing citing it in that scope.

## Files
- `internal/engine/consolidate/finish.go`: `RefreshPayload` marshals as `mental_model_id`.
- `internal/engine/consolidate/apply.go`:
  - `writeActions` returns the facts that the landed actions cite, as `applyOutput.cited`.
  - The `stampable` doc comment now covers the run-written scopes.
- `internal/engine/consolidate/batch.go`: `run.recordCited` adds the batch's scope to `r.cited` after
  each apply.
- `internal/engine/consolidate/run.go`: the `cited` field doc.
- `internal/engine/mentalmodel/reconcile.go`: `RunJob` decodes through `decodeRefreshPayload`, which also
  accepts the legacy `model_id` key.
- Tests:
  - `internal/engine/consolidate/stamp_test.go` (new) and `run_test.go`, which gets the strict payload-key
    check.
  - `internal/engine/mentalmodel/reconcile_test.go` (new).
  - `test/e2e/scenarios_test.go`, with one new scenario.
- `docs/rules.md` (rows: consolidate every scope; consolidate triggers refreshes),
  `docs/decisions/1800-refresh-payload-one-shape.md` and `docs/decisions/1801-stamp-recheck-run-cited-scopes.md`.

No interface, constructor or frozen-path changes. No CCR.
